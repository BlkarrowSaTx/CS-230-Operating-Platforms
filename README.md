## Reflection 

### Briefly summarize The Gaming Room client and their software requirements.

The client for this project was The Gaming Room. They have an existing game that runs on Android called Draw It or Lose It. There are teams of players who have to guess what is being drawn from an image. The image will reveal itself bit by bit and the players have until the time runs out. The Gaming Room wanted their game to be more than just on android they wanted a web application that can run on many different platforms. I was tasked with creating a design for this application. The design would include what requirements the program would need, what components it should consist of and what platform I think it should run on. There would be games that have teams and players and the game name, team name and player name all have to be different from each other.

### What did you do particularly well in developing this documentation?

I feel that I did a good job at keeping my design based around what the client wanted. All the requirements I put in are relevant to what they were asking for and the class diagram I came up with also has relevance to the clients wants and the requirements. When deciding what platforms I would recommend I kept the clients needs in mind as well. I tried to better myself on the explanation of my topic. I wanted the client to understand why I decided on Linux and how I decided to apply it to their software but also wanted my development team to know what they needed to implement.

### What about the process of working through a design document did you find helpful when developing the code?

Writing my design allowed me to write my code with less thought. Since I had created my class diagram I knew that I would want a Entity that the Game, Team and Player would inherit from. I could see in my class diagram where I wanted to apply the Singleton and Iterator design patterns. So when I sat down to code I wasn't having to think of these things. I had all of this planned out from my design.

### If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it? 

I would probably go back and add more information to my Platform choice. I have all of my information about Linux, Mac, Windows and Mobile but I could have gone into more detail on things like pricing and other facts that may benefit the client. I could also have written more on how this will play out if there was a large amount of users. By adding these details to my document I feel like I could better represent my reasoning for why I chose to use Linux.

### How did you interpret the user's needs and implement them into your software design? Why is it so important to consider the user's needs when designing?

When thinking about what the user would want I focused on what the client told me they wanted. Since they already had a game on Android I could use that as a guide to create my software design. I thought of what the user would experience when playing and added things that the user would want. It is important to consider the user when designing your software because if you create software that the user does not want they are not going to use it. There would be no point in creating a piece of software if the person using it isn't satisfied with it. If I only thought about what would be easy for me to code I may produce software that meets the clients requirements but isn't what the user is looking for.

### How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?

When approaching my design I broke down the clients problem and began to make requirements for what my software would need. After I had my list of requirements I created my class diagram. Next I decided which platform would be best for my clients application and listed pros and cons for my options. Once I had this information I created my recommendation on Operating Platform, Storage, Memory, Network and Security. In the future I would do more research and use different methods to get information on what the user would want from there piece of software. Maybe doing user stories and prototyping some of my ideas would allow me to better understand the clients wants.
